# 描画結果のA/B比較

目的は「差があった」ではなく **「この差はこの変更に帰属できる」** と言い切れる状態を作ること。

## 1. まず対照を取る（省略禁止）

**同一条件で2回撮って差分を測り、それを「再現性の下限」とする。**
これが実質ゼロであることを確認して初めて、A/Bの差をその変更に帰属できる。

実測例: 同一シェーダで2回撮影 → 8bit値の差が2を超えた画素は0、最大差1。
自動露出まで含めて実行間で完全に再現した。この下限が取れていない状態での比較は無意味。

**逆向きの対照も要る。** 差分ゼロは合格ではない。「片方が実行されていない」可能性を先に潰すこと。
A/Bトグルを入れたら、まず**わざと大きく壊した値**で差が出ることを確認してから本番の値に戻す。

## 2. 条件を揃える

- **TAAは切る。** 時間方向に蓄積するため、フレームレートの揺れがそのまま画素差になる
- **同じ起動手順で撮る。** シーンを切り替えてもEV100(自動露出)は引き継がれる。
  空の輝度が動いていたら、変更ではなく露出を疑う
- **UI操作に依存させない。** 起動時点で目的の状態になるよう一時デバッグ改変を入れるのが確実。
  ImGuiのクリックは他セッションとの競合や上書きで落ちることがあり、比較のたびに同じ操作を
  再現するのは信頼性が低い(起動シーンの固定など)
- **前処理は両側に等しく掛ける。** 片側だけの平滑化・リサイズ・色変換は指標を汚染する
  (片側だけの平滑化が尖塔を消し、汚染された指標に合わせて形をいじってしまった事例あり)

## 3. シェーダだけの変更でもビルドが要る

**`.hlsl`はビルド時に`.kshader`へ焼かれ、出力フォルダには`.hlsl`が置かれない。**
シェーダだけの比較でも、A側とB側それぞれでビルドを通す必要がある
(`KurenaiShaderPacker`が更新日時で増分に動くので、変えた`.hlsl`のぶんだけ焼き直される)。

**焼き直しが走ったことをビルドログで確認すること。** 「すべて最新です」と出ていたら
`.kshader`は変わっておらず、**A/Bのどちらも同じシェーダーで撮っている**
――対照実験としては「片方が実行されていない」状態そのものになる。

HLSLのコンパイルエラーはビルドで落ちるので、別途 `shader-check` を通す必要はない。

## 4. 差分の出し方

**数値と画像の両方を出す。数値だけでは「どこが」変わったか分からない。**

下のワンライナーは**最終画面の8bit PNG専用**。中間バッファ(G-Buffer・深度・間接光)を
線形のfloatのまま比べるなら `-dumptex` と `Tools/texdump_inspect.py`(`shader-debug` スキル)。
**8bitでは丸めだけで下限が生まれ、その下限に隠れて読めない差がある。**

- 数値: 差が一定値(例: 8bit値で2)を超えた画素数、最大差
- 画像: 増幅した差分画像と、切り出しの並置

```powershell
python -c "
from PIL import Image, ImageChops
import numpy as np
a = np.asarray(Image.open('a.png').convert('RGB'), dtype=np.int16)
b = np.asarray(Image.open('b.png').convert('RGB'), dtype=np.int16)
d = np.abs(a - b)
print('max diff :', d.max())
print('px > 2   :', int((d.max(axis=2) > 2).sum()))
Image.fromarray((np.clip(d * 16, 0, 255)).astype('uint8')).save('diff_x16.png')
"
```

## 5. 「変わった」ではなく「正しく変わった」を測る

不変条件(他の領域が変化していないこと)だけを確認して合格にしない。
**変えた領域については、期待した方向に期待した量だけ動いたかを測る。**
平面反射の実装で不変条件だけを見て、水面全面の破綻を見逃した事例がある。

## 6. 参考画像と比べるとき

- **必ず並べて比べる。** 単独で眺めると東西反転すら見逃す
- **自動抽出した値は描き戻して検証するまで信用しない**
- **残差が大きいときは、モデルより先にカメラを疑う。** 順番は 測定器 → 撮影条件 → モデル。
  大きな残差3件のうち2件は方位とカメラ高さの取り違えだった
- **差分は目視で追わず地図にする。** 「どこが足りないか」は方位×高さで数えると1回で確定する。
  目視で3回追いかけて場所を外した事例がある
- **手続き生成の見た目は実現値を複数取る。** 1枚は分布ではない。
  凍結した1枚で原因を帰属すると丸ごと外す

## 7. 原因の帰属

**候補を2つ潰しただけで残りに帰属しない。** 項を1つずつ止めて測ること。
消去法で決めた結果、第三の要因が単独で効いていた事例がある。

**帰属を報告する前に `double-check`。** 原因の断定と測った数値は、
`verifier` と Codex の2系統に当てる(線引きは `double-check` 2節)。

## 関連

- 起動・撮影・クリックの手順は `verify-app` スキル
- マージ前のHLSL一括検証は `shader-check` スキル
- 中間バッファの値を数値で読む・シェーダへ計装を入れるのは `shader-debug` スキル
- 報告前の検算: `double-check`
