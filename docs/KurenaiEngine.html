KurenaiEngine APIリファレンス

このドキュメントは、KurenaiEngineLibrary.dll / KurenaiEngine3D.dll / KurenaiEngine2D.dll が公開するAPIを使ってアプリケーションを作成するための 情報をまとめたものです。すぐに動かしたい場合は 3Dサンプル向けの Kurenai::KurenaiEngine3D や2Dサンプル向けの Kurenai::KurenaiEngine2D を、より自由度の高い描画を組みたい場合は 低レベルAPI一式(Kurenai::RHI / Kurenai::Core / Kurenai::Assets、まとめて「Library」)を直接利用できます。

1. アーキテクチャ

KurenaiEngineは 3つのDLLに分かれてビルドされます。 KurenaiEngineLibrary.dll(共通基盤。RHI抽象化層・Window・Camera・ モデル/シーン読み込みと、3D/2D共通の土台KurenaiEngineBaseを公開)、 KurenaiEngine3D.dll、KurenaiEngine2D.dllで、3D/2Dはいずれも KurenaiEngineLibraryにのみ依存し、互いには依存しません。 

KurenaiEngine/
  KurenaiEngineLibrary.vcxproj  ← 共通基盤(DynamicLibrary)
  KurenaiEngine3D.vcxproj       ← 3D API(DynamicLibrary)。Libraryにのみ依存
  KurenaiEngine2D.vcxproj       ← 2D API(DynamicLibrary)。Libraryにのみ依存
  Source/
    Engine/    ← 公開API(このドキュメントで説明する全て)
      KurenaiTypes.h        GraphicsAPI enum, DLLごとのエクスポートマクロ
      KurenaiEngineBase.h   3D/2D共通の土台(非公開コンストラクタ。KurenaiEngineLibraryが公開)
      KurenaiEngine3D.h     3Dサンプル向け公開クラス(KurenaiEngine3Dが公開)
      KurenaiEngine2D.h     2Dサンプル向け公開クラス(KurenaiEngine2Dが公開)
    Library/   ← 低レベルAPI(RHI抽象化層、Window、Camera、モデル読み込みなど。4章参照。KurenaiEngineLibraryが公開)
      RHI/ Core/ Assets/
  Shaders/3D/  ← KurenaiEngine3Dが内部で使うHLSLシェーダ一式
  Shaders/2D/  ← KurenaiEngine2Dが内部で使うHLSL(Sprite2D.hlsl)

Source/Engine/ と Source/Library/ はどちらも公開APIで、 どちらのクラス・関数も対応するDLLから __declspec(dllexport) されています (Source/Library/RHI/DX11, DX12 配下のバックエンド実装クラス自体は 非公開で、RHI::IRHIDevice などのインタフェース越しにのみ利用します)。 用途に応じて使い分けてください。

  • まず動かしたい・定番の3D/2D表現で十分な場合 → KurenaiEngine3D / KurenaiEngine2D(2章・3章)
  • 独自の描画パイプラインを組みたい場合(カスタムシェーダ、独自のポストエフェクト、 スプライト以外の2D表現など) → Library の低レベルAPI(4章)を直接利用

サンプルプログラムを新規に作成する場合、プロジェクトのインクルードディレクトリには KurenaiEngine/Source/Engine を追加し(KurenaiEngine3D.h などを includeするため)、KurenaiEngineLibrary.vcxproj と、使う方(KurenaiEngine3D.vcxproj または KurenaiEngine2D.vcxproj)の2つへプロジェクト参照を張ってください (Samples/Sample3D, Samples/Sample2D の .vcxproj を 参考にできます。DLLを経由したプロジェクト参照は推移的にリンクされないため、Libraryへの参照は 省略できません)。Library の低レベルAPIも使う場合は KurenaiEngine/Source/Library もインクルードディレクトリに追加してください (RHI/IRHIDevice.h のように Library を起点とした相対パスでincludeする)。 実行ファイルの出力先はビルドの度に各DLLが生成される場所(リポジトリ直下の Build\Bin\<Platform>\<Configuration>\<プロジェクト名>\)と揃えてください。 DLLは実行ファイルと同じフォルダに置かれていないと起動時に読み込めません。

2. Kurenai::KurenaiEngine3D — 3Dサンプル向け公開API完結型

KurenaiEngine3D は、Deferred Shading(G-Buffer: Albedo/Normal/Metallic-Roughness+ 深度)によるPBRレンダリング、シャドウマッピング、IBL(環境光)、SSAO/SSIL(間接光)、SSR(反射)、 複数シーンの切り替え、ImGuiによる設定パネル一式までを内包した完結型の3Dレンダラーです。 構築して Run() を呼ぶだけでウィンドウが開き、ユーザーが閉じるまでブロックします。 

#include "KurenaiEngine3D.h"
#include "KurenaiTypes.h"

int WINAPI wWinMain(HINSTANCE, HINSTANCE, LPWSTR, int)
{
    CoInitializeEx(nullptr, COINIT_APARTMENTTHREADED); // WICテクスチャ読み込みに必要

    Kurenai::KurenaiEngine3D engine(Kurenai::GraphicsAPI::DX11); // またはDX12
    engine.Run();

    CoUninitialize();
    return 0;
}
namespace Kurenai
{
    class KurenaiEngine3D : public KurenaiEngineBase
    {
    public:
        explicit KurenaiEngine3D(GraphicsAPI api = GraphicsAPI::DX11, uint32_t renderWidth = 1280, uint32_t renderHeight = 720);
        ~KurenaiEngine3D();
        void Run();
    };
}
  • renderWidth/renderHeight はG-Bufferなどの内部レンダリング解像度 (ウィンドウサイズとは独立)。ウィンドウは常に1280x720で開始し、リサイズ可能。表示時はアスペクト比を 保ってレターボックス/ピラーボックス表示される。
  • Run() を呼ぶと以下を自動的に行う(設定変更やシーン読み込みはすべて ImGuiパネル経由):
    • WASD で移動、E/Q で上下移動、Shift で高速移動
    • 右クリックを押しながらマウス移動でカメラ回転
    • F1 でImGuiパネルの表示/非表示切り替え
    • 画面左上のImGuiパネル(Scenes / Post Processing / Render Targets / Lighting / Profiler)で 表示アセットの切り替え、シャドウ/AO(SSAO・SSIL)/SSRのON・OFFやパラメータ調整、デバッグ表示 バッファの選択、時刻(昼夜サイクル)とEV100(露出)の調整、ポイント/スポットライトの 一覧・追加・削除・編集、FPS/CPU/GPUの計測値確認ができる
  • 表示できるシーンはビルド済みバイナリに組み込み済み(Sponza / Bistro (McGuire) Exterior / Bistro (McGuire) Interior / White Surface Test / Light Test)。カスタムモデルの追加や、 シーン一覧の外部からのカスタマイズは現状の公開APIではサポートしていない(Run() を 呼ぶ以外のカスタマイズ余地がないのが KurenaiEngine3D の設計上の割り切り)。
  • コンストラクタに渡した GraphicsAPI に応じてDX11/DX12いずれかのバックエンドで 動作する。

3. Kurenai::KurenaiEngine2D — 2Dサンプル向け公開API軽量API

KurenaiEngine2D は正射影カメラとアルファブレンドによるスプライト描画を 提供する軽量なAPIです。KurenaiEngine3D と異なり内部でゲームループを回さず、 フレームごとの描画呼び出しをアプリケーション側の while ループから行います。 

namespace Kurenai
{
    class TextureHandle
    {
    public:
        TextureHandle() = default;
        bool IsValid() const;
    };

    class KurenaiEngine2D : public KurenaiEngineBase
    {
    public:
        KurenaiEngine2D(const std::wstring& title, uint32_t width, uint32_t height, GraphicsAPI api = GraphicsAPI::DX11);
        ~KurenaiEngine2D();

        TextureHandle LoadTexture(const std::wstring& filePath, bool sRGB = false);
        TextureHandle CreateSolidColorTexture(uint8_t r, uint8_t g, uint8_t b, uint8_t a);

        void BeginFrame(float clearR, float clearG, float clearB, float clearA = 1.0f);
        void DrawSprite(float x, float y, float width, float height, float rotationRadians,
                         TextureHandle texture, float r, float g, float b, float a);
        void DrawCircle(float x, float y, float radius, float r, float g, float b, float a);
        void DrawLine(float x1, float y1, float x2, float y2, float thickness, float r, float g, float b, float a);
        void DrawRoundedRect(float x, float y, float width, float height, float cornerRadiusPixels,
                              float r, float g, float b, float a,
                              float borderThicknessPixels = 0.0f,
                              float borderR = 0.0f, float borderG = 0.0f, float borderB = 0.0f, float borderA = 0.0f);
        void DrawText(float x, float y, const std::wstring& text, float fontSize, float r, float g, float b, float a,
                      bool bold = false, TextAlign align = TextAlign::Center, TextVerticalAlign verticalAlign = TextVerticalAlign::Middle);
        float MeasureText(const std::wstring& text, float fontSize, bool bold = false);
        void EndFrame(bool vsync = true);
    };
}

KurenaiEngineBase から継承する共通機能(ウィンドウ・メッセージループ):

bool ShouldClose() const;   // ウィンドウが閉じられたか
void PumpEvents();          // メッセージポンプ。毎フレーム呼ぶ
void Close();               // プログラムからウィンドウを閉じる(Escキー等に割り当てるとよい)
uint32_t GetWidth() const;
uint32_t GetHeight() const;
HWND GetWindowHandle() const; // 生成したウィンドウのHWND(ScreenToClient等、Win32入力処理に使う)

3.1 座標系

ワールド座標=ウィンドウのピクセル座標(原点は画面左下、Y-upの標準的な2Dゲーム座標系)。 DrawSprite の x, y はスプライト中心の位置、width, height は ピクセル単位のサイズ、rotationRadians は画面奥から手前を見た反時計回りのZ軸回転。

3.2 使い方

#include "KurenaiEngine2D.h"
#include "KurenaiTypes.h"

using namespace Kurenai;

int WINAPI wWinMain(HINSTANCE, HINSTANCE, LPWSTR, int)
{
    CoInitializeEx(nullptr, COINIT_APARTMENTTHREADED);

    KurenaiEngine2D renderer(L"My 2D Game", 1280, 720, GraphicsAPI::DX11);

    TextureHandle playerTexture = renderer.LoadTexture(L"Assets/player.png", false);
    float x = 640.0f, y = 360.0f;

    while (!renderer.ShouldClose())
    {
        renderer.PumpEvents();
        if (GetAsyncKeyState(VK_ESCAPE) & 0x8000)
        {
            renderer.Close();
        }

        // 入力処理・座標更新はアプリケーション側の責任(WinAPIを直接使う。5章参照)
        if (GetAsyncKeyState('D') & 0x8000) x += 4.0f;
        if (GetAsyncKeyState('A') & 0x8000) x -= 4.0f;

        renderer.BeginFrame(0.1f, 0.1f, 0.15f);
        renderer.DrawSprite(x, y, 64.0f, 64.0f, 0.0f, playerTexture, 1.0f, 1.0f, 1.0f, 1.0f);
        renderer.EndFrame(true);
    }

    CoUninitialize();
    return 0;
}
  • LoadTexture / CreateSolidColorTexture はロード時にまとめて呼び、 返ってきた TextureHandle を保持しておいて毎フレームの DrawSprite に 渡す(KurenaiEngine2D が内部でテクスチャの実体を所有し続けるため、 renderer が生存している間は有効)。
  • DrawSprite の r, g, b, a はテクスチャに乗算されるティント色。 a < 1.0 で半透明合成される(常にアルファブレンド有効。深度テストは行わないため、 重なり順は呼び出し順で決まる — 先に呼んだスプライトほど背面に描かれる)。
  • BeginFrame/EndFrame は1フレームにつき必ず1回ずつ呼ぶ。 DrawSprite/DrawCircle/DrawLine/DrawRoundedRectはその間に好きな回数呼べる。
  • DrawCircleは中心(x, y)・半径radiusの塗り円をふちのアンチエイリアス付きで描画する (テクスチャ不要、ピクセルシェーダーの距離場でマスクする)。DrawLineは (x1, y1)-(x2, y2)を結ぶ太さthicknessの線分を、内部的には 回転・拡縮した矩形としてDrawSpriteと同じパイプラインで描画する。いずれも r, g, b, aは塗りつぶし色で半透明可。
  • DrawRoundedRectは中心(x, y)、サイズwidth x height、 角丸半径cornerRadiusPixels(ピクセル単位)の角丸矩形を、DrawCircleと同様 テクスチャ不要のピクセルシェーダー距離場(SDF)でふちをアンチエイリアスしながら描画する。 borderThicknessPixelsを0より大きくすると、塗りの内側にborderR/G/B/Aの 枠線をさらに重ねて描画する(既定は枠線なし)。UIのボタンやパネル背景など、角丸+枠線を 1回の描画コマンドで表現したい場合に使う。
  • DrawTextは既定(align = TextAlign::Center, verticalAlign = TextVerticalAlign::Middle) では(x, y)をテキスト中央基準としてtextを描画する。fontSizeは おおよその文字高さ(ピクセル単位)。コンストラクタ内でGDI(Yu Gothic UI)によりASCII印字可能文字 (0x20〜0x7E)一式をビットマップフォントとしてラスタライズしたテクスチャアトラスを 生成し、1文字ごとにアトラス内の該当矩形をサンプルするテクスチャ付き矩形として描画する (頂点シェーダーでUVをオフセット・スケールする点以外はDrawSpriteと同じパイプラインを使う)。 厳密なフォントレンダリング(ヒンティング等)は行わないため、HUD表示程度の可読性を想定している。
  • bold = trueを指定すると、通常とは別に構築される太字(FW_BOLD)アトラスを 使って描画する(通常版と太字版は別テクスチャ・別文字集合として独立に管理され、コンストラクタで 両方ともASCII一式が事前構築される)。
  • align(TextAlign::Left/Center(既定)/Right)でxの意味が変わり、 verticalAlign(TextVerticalAlign::Bottom/Middle(既定)/Top)でyの意味が変わる。 既定のまま(align = Center, verticalAlign = Middle)ならボタンの中心座標を そのまま渡すだけで正確に中央揃えできる。align = Center/Rightまたは verticalAlign = Middle/Bottomの場合、内部でMeasureText相当の幅・高さ計測を 行ってから描画開始位置を決めるため、呼び出し側で幅・高さを計算する必要はない (align = LeftかつverticalAlign = Topの組み合わせのみ、計測なしで(x, y)を そのままテキスト左上基準として使う、最も低コストな経路になっている)。
  • MeasureText(text, fontSize, bold)は指定した文字列・サイズ・太さで描画した場合の 実測済み幅(ピクセル単位、各グリフのAdvancePixelsの合計)を返す。DrawTextと同様、 アトラス未収録の文字はその場では幅0として扱われ、次のBeginFrame()でアトラスに追加された 以降は正しい幅が返る。ボタン幅の自動計算など、中央揃え以外の用途で幅そのものが必要な場合に使う。
  • かな漢字を含む任意のUnicode文字(BMP範囲)にも対応する。ASCII以外の文字は 初回のコンストラクタ実行時点ではアトラスに含まれていないため、DrawTextがアトラス未収録の 文字を検出すると、その文字だけをその場では描画せず、次のBeginFrame()の先頭でアトラスへ 追加してから以降のフレームで表示する(DX12のCreateTextureFromMemoryがコマンドリストを フラッシュ・リセットする都合上、通常の描画コマンドを積んだ後のフレーム中にアトラスを作り直すと レンダーターゲット/パイプラインステートの設定が失われクラッシュするため、追加は BeginFrame()の先頭でのみ行う設計になっている)。そのため新しい文字が最初に画面へ 現れる瞬間だけ1フレーム欠けることがあるが、通常のHUD表示(同じ文字列を毎フレーム描画し続ける用途) では気付かない程度の遅延で済む。

4. Library — 低レベルAPI上級者向け

KurenaiEngine3D/KurenaiEngine2D では対応できない独自の描画を組みたい 場合、Kurenai::RHI(DX11/DX12を抽象化したレンダリングAPI)・Kurenai::Core (ウィンドウ・カメラ)・Kurenai::Assets(モデル読み込み)を直接利用できます。 実際に KurenaiEngine3D/KurenaiEngine2D 自身もこのLibraryの上に 実装されています。

4.1 基本的な流れ

Core::Window window(L"My App", 1280, 720);
auto device = RHI::CreateDX11Device(); // または RHI::CreateDX12Device()
auto swapChain = device->CreateSwapChain(window.GetHandle(), window.GetWidth(), window.GetHeight());

// シェーダ・パイプラインステート・バッファ・テクスチャ・サンプラーを生成(通常は起動時に1回)
auto vs = device->CreateShader({ RHI::ShaderStage::Vertex, L"Shader.hlsl", "VSMain" });
auto ps = device->CreateShader({ RHI::ShaderStage::Pixel,  L"Shader.hlsl", "PSMain" });

RHI::PipelineStateDesc psoDesc;
psoDesc.InputLayout = { { "POSITION", 0, RHI::Format::R32G32B32_Float, 0 } };
psoDesc.VertexShader = vs.get();
psoDesc.PixelShader = ps.get();
psoDesc.RenderTargetFormats = { RHI::Format::R8G8B8A8_UNorm };
auto pipelineState = device->CreatePipelineState(psoDesc);

RHI::IRHICommandList* cmd = device->GetImmediateCommandList();
while (!window.ShouldClose())
{
    window.PumpMessages();

    cmd->SetRenderTarget(swapChain.get()); // スワップチェーン付属の深度バッファも同時にバインドされる
    cmd->ClearRenderTarget({ 0.05f, 0.05f, 0.08f, 1.0f });
    cmd->SetViewport({ 0, 0, (float)window.GetWidth(), (float)window.GetHeight(), 0.0f, 1.0f });
    cmd->SetPipelineState(pipelineState.get());
    // ... SetVertexBuffer / SetConstantBuffer / SetTexture / SetSampler / Draw ...

    swapChain->Present(true);
}

RHI::CreateDX11Device() / RHI::CreateDX12Device() で生成する。主なメソッド:

std::unique_ptr<IRHITexture>   CreateTextureFromImage(const RHI::TextureImage& image);
std::unique_ptr<IRHITexture>   CreateSolidColorTexture(uint8_t r, uint8_t g, uint8_t b, uint8_t a);
std::unique_ptr<IRHITexture>   CreateTextureFromMemory(uint32_t width, uint32_t height, const void* pixelsRGBA8);

CreateTextureFromFile は拡張子(.dds/.tga/その他はWIC経由で png・jpg・bmp等)から自動判別する。sRGB=true はベースカラー等「見た目の色」を持つ テクスチャに、法線マップ等のデータ系テクスチャにはfalseを指定する。 CreateTextureFromMemory はRGBA8(1ピクセル4バイト、行間パディングなしのタイトパッキング)の ピクセルデータから直接テクスチャを作成する(実行時に生成したデータをアップロードする用途向け。 KurenaiEngine2D::DrawTextのフォントアトラス生成で使用)。

SamplerDesc(RHIDesc.h)はFilter(SamplerFilter::Linear / Anisotropic)とMaxAnisotropyを持つ。既定値はAnisotropic・16xで、 浅い角度で見る面(床・路面など)のボケを抑える。AddressU/V/Wは常にWrap固定のため公開していない。

RHI::TextureImage::LoadFromFile(filePath, sRGB)(TextureImage.h)は ファイルのデコードのみを行い、GPUデバイスを必要としない静的関数。CreateTextureFromFileは 内部でこれを呼んでからCreateTextureFromImageでGPUリソース化しているだけであり、 両者を分離しているのは、デコード(CPU処理)をワーカースレッドで並列に行い、GPUリソース作成 (デバイスに紐づくため直列)だけを呼び出し元スレッドで行うため(4.6のAssets::LoadModelの 並列プリフェッチが実例)。

void Dispatch(uint32_t threadGroupCountX, uint32_t threadGroupCountY, uint32_t threadGroupCountZ);

SetShaderResourceBufferはBufferUsage::StructuredReadOnlyで作成した バッファをStructuredBuffer<T>としてピクセルシェーダへ読み取り専用でバインドする (要素数が可変で定数バッファに収めるには大きい配列向け。詳細は4.4参照)。スロット空間は SetTextureと共通(t0〜t6)のため、同じ描画内で テクスチャとスロットが衝突しないよう呼び出し側で調整すること。DX11バックエンドでは SetTextureと同様ピクセルシェーダからのみ参照できる。

4.3.1 コンピュートシェーダー

ShaderStage::ComputeでCreateShaderしたシェーダーを CreateComputePipelineStateに渡してコンピュート用パイプラインステートを作る。 グラフィックス用のSetPipelineState/SetConstantBuffer/SetTextureとは 別のレジスタ空間(DX12では専用のルートシグネチャ)を使うため、必ずSetCompute…系の 専用APIを使うこと。 

auto cs = device->CreateShader({ RHI::ShaderStage::Compute, L"Blur.hlsl", "CSMain" });
auto pso = device->CreateComputePipelineState({ cs.get() });
auto output = device->CreateUAVTexture(width, height, RHI::Format::R8G8B8A8_UNorm); // RWTexture2D

cmd->SetComputePipelineState(pso.get());
cmd->SetComputeTexture(0, inputTexture.get());              // t0 (SRV, 読み取り専用)
cmd->SetComputeUnorderedAccessTexture(0, output.get());     // u0 (RWTexture2D)
cmd->Dispatch((width + 7) / 8, (height + 7) / 8, 1);         // HLSL側は[numthreads(8, 8, 1)]

構造化バッファ(RWStructuredBuffer)を使う場合はBufferDesc::Usage = BufferUsage::Structured でCreateBufferし、SetComputeUnorderedAccessBufferでu0〜u3にバインドする。 Dispatchの直後に書き込み完了を保証するUAVバリアが自動的に発行されるため、続けて同じ リソースを別のDispatchやグラフィックスパスで読んでも呼び出し側でバリアを意識する必要はない。 DX11バックエンドも同じAPIで動作するが、UAVはDispatch呼び出しの範囲内でのみバインドされ、 呼び出し後に自動的にアンバインドされる(同一リソースをUAVとSRVへ同時バインドできないDX11の制約のため)。

4.3.2 Hi-Zミップチェーン

CreateHiZTexture(width, height, mipLevels)は、単チャンネル(R32_Float)で width/heightから1x1までのフルミップチェーンを持つテクスチャを作る。 通常のCreateUAVTextureが常に1ミップしか持たないのに対し、こちらは ミップごとに個別のUAVを張るため、SetComputeUnorderedAccessTextureの 第3引数mipLevelで「どのミップに書き込むか」を指定できる。SRV側は全ミップをまとめて見る 1枚のビューになっており(SampleLevelで任意のミップを読む用途、ミップ0のコピー元は別テクスチャ)、 ミップ単位で読みたい場合はUAVを読み取り専用として使う(下記例のように隣接ミップを2枚ともUAVでバインドする)。 

auto copyCs = device->CreateShader({ RHI::ShaderStage::Compute, L"HiZ.hlsl", "CSCopy" });
auto copyPso = device->CreateComputePipelineState({ copyCs.get() });
auto downsampleCs = device->CreateShader({ RHI::ShaderStage::Compute, L"HiZ.hlsl", "CSDownsample" });
auto downsamplePso = device->CreateComputePipelineState({ downsampleCs.get() });

const uint32_t mipLevels = /* floor(log2(max(width, height))) + 1 */;
auto hiZTexture = device->CreateHiZTexture(width, height, mipLevels);

// ミップ0: 通常の深度テクスチャ(1ミップ)からコピーする
cmd->SetComputePipelineState(copyPso.get());
cmd->SetComputeTexture(0, depthTexture.get());                    // t0 (SRV)
cmd->SetComputeUnorderedAccessTexture(0, hiZTexture.get(), 0);    // u0 = ミップ0
cmd->Dispatch((width + 7) / 8, (height + 7) / 8, 1);

// ミップ1以降: 1つ前のミップを読み、2x2ブロックの最小値(Reverse-Zのため最も遠い深度)を次のミップへ書く
cmd->SetComputePipelineState(downsamplePso.get());
for (uint32_t mip = 1; mip < mipLevels; ++mip)
{
    cmd->SetComputeUnorderedAccessTexture(0, hiZTexture.get(), mip - 1); // u0 = 読み取り元ミップ
    cmd->SetComputeUnorderedAccessTexture(1, hiZTexture.get(), mip);     // u1 = 書き込み先ミップ
    cmd->Dispatch(/* 出力ミップの幅高さに応じたグループ数 */);
}

最小値でダウンサンプルするのは、このエンジンがReverse-Z(近平面=1.0/遠平面=0.0、深度比較はGREATER)を 使っているため。あるブロックの最小深度値は 「そのブロック内で最も遠い可視サーフェス」を表し、候補オブジェクトの最も近い点でさえこの値より 奥であれば、ブロック内のどのピクセルにも遮蔽されていることが保証できる(非Reverse-Zで最大値を 取る一般的なHi-Zカリング手法を、Reverse-Zの向きに合わせて反転させたもの)。KurenaiEngine3D はG-Buffer深度からこのミップチェーンを毎フレーム構築しているが、現時点ではオクルージョンカリングや SSRのレイマーチング高速化といった利用箇所は未実装で、デバッグ表示(Render Targets - Hi-Z)でのみ 内容を確認できる。

バインドスロットの上限(DX12バックエンドが固定のルートシグネチャで実装されているため、 DX11/DX12共通でこの範囲を守る必要がある):

定数バッファ更新の制約: CreateBuffer にInitialDataを 渡すかどうかで、後からUpdateBufferできるかがDX11/DX12で挙動が変わる。

  • 毎フレーム更新する定数バッファ(BufferUsage::Constant): InitialData = nullptr で作成し、以後UpdateBuffer()で毎フレーム書き込む(DX11ではInitialDataを渡すと IMMUTABLEになり以後の更新が失敗するため、必ずnullptrで作成すること)。
  • 頂点/インデックスバッファ(BufferUsage::Vertex/Index): InitialDataを渡して作成する静的ジオメトリ専用。生成後にUpdateBufferしては いけない(DX12ではGPU読み取り専用のDEFAULTヒープに配置されるため未定義動作になる)。移動・回転・ 拡縮は定数バッファ経由のワールド行列で表現する。

4.4 その他のRHI型

IRHIBuffer / IRHITexture / IRHIShader / IRHIPipelineState / IRHISampler / IRHISwapChain はいずれも 中身を持たない不透明なハンドル型。std::unique_ptr<IRHIXxx>として保持し、 IRHICommandListの各メソッドに生ポインタ(.get())で渡す。 RHIDesc.h(BufferDesc, ShaderDesc, InputElementDesc, PipelineStateDesc, ComputePipelineStateDesc)とRHIEnums.h (ShaderStage: Vertex/Pixel/Compute、 BufferUsage: Vertex/Index/Constant/Structured(コンピュートシェーダー用のRWStructuredBuffer)/ StructuredReadOnly(CPUから毎フレームUpdateBufferで書き換え、 シェーダからはStructuredBuffer<T>として読み取り専用。SetShaderResourceBufferで グラフィックスパイプラインへバインドする。要素数が可変で定数バッファに収めるには大きい配列 — KurenaiEngine3Dのポイント/スポットライトリストが実例 — 向け)、 Format, BlendMode など)に描画リソースの 記述構造体・列挙型がまとまっている。PipelineStateDesc::BlendModeには Opaque(既定・不透明)、AlphaBlend(標準アルファブレンド)、 Additive(加算合成。炎・光などの発光エフェクト向け)、 Multiply(乗算合成。影・すりガラスなどの減光表現向け)、 PremultipliedAlpha(事前乗算済みアルファブレンド)を指定できる。 IRHIGPUProfiler(GPUタイムスタンプ計測)、 IRHIImGuiBackend(ImGui連携)も同様に公開されている。

4.6 Assets::LoadModel

KurenaiPacker.exe(本リポジトリ同梱のオフラインアセットビルドツール)が事前生成した .kmodel(マニフェスト)・.kgeom(ジオメトリ実体)・.ktex (BC7圧縮・ミップ生成済みテクスチャ実体)の3種のファイルを読み込み、頂点/インデックスバッファと テクスチャをRHI経由でGPUへアップロード済みの状態で Model(Meshの配列) として返す。filePathには.kmodelのパスを渡す (.gltf/.fbx等のソースモデルを直接渡すことはできない。事前に KurenaiPacker.exeで変換すること。使い方はREADME.md参照)。

4.6.1 ライトの読み込み(Model::Lights)

モデルファイルにポイント/スポット/平行光が含まれる場合、Model::Lights (std::vector<Assets::Light>)として読み込まれる。glTFは KHR_lights_punctual 拡張、FBXはLightノードから読み込む(抽出自体はKurenaiPacker.exeが パック時に行い、.kmodelのLightEntry[]として格納する。ランタイムはそれを そのまま読むだけで、assimpには依存しない)。 

enum class LightType { Directional, Point, Spot };

struct Light
{
    LightType Type;
    float Position[3];         // ローカル座標(モデル自身の空間。Directionalでは未使用)
    float Direction[3];        // 光が進む向き(正規化済み)。Spot/Directionalで使用
    float Color[3];            // 線形色。最大成分が1になるよう正規化済み
    float Intensity;           // 測光量。Point/Spotはカンデラ(cd)、Directionalはルクス(lx)
    float Range;                // 影響半径。Directionalでは未使用
    float SpotInnerConeAngle;   // ラジアン。Spotのみ
    float SpotOuterConeAngle;
    bool Enabled;
    std::string Name;
};
  • Intensityの単位は物理量。glTFはKHR_lights_punctualの値 (カンデラ/ルクス)をそのまま読み込むため正確。FBXには物理単位が存在しないため、DCC側の Intensityプロパティをカンデラ相当として近似する(精度は保証されない)。
  • 表示上の明るさは測光量に実在の写真露出値EV100(KurenaiEngine3Dの Lightingパネルの「EV100」)を直接掛けて求める(exposure = 1 / (1.2 * 2^EV100))。 太陽光・環境光にも同じ露出が一様にかかる、シーン全体で単一の設定になっている。EV100は値が 大きいほど明るいシーンを表す実在の写真用語であり、値を上げるほど描画は暗くなる (Photoshop等の「露出」スライダーとは向きが逆なので注意)。
  • RangeはglTFにノードのメタデータPBR_LightRangeがあればその値を 使う。無ければ打ち切り輝度からEV100=15.0(既定値)を仮定して逆算した推定値が入る (この推定はKurenaiPacker.exeのパック時に一度だけ行われるため、後からEV100を大きく変更すると 実際に見えるべき範囲と合わなくなることがある。その場合はImGuiでRangeを手動調整する)。
  • 平行光は太陽光との二重照明を避けるため、読み込み時は既定でEnabled = false になる(ImGuiから有効化できる)。
  • エリアライト(球・チューブ・矩形)は未対応。glTFの KHR_lights_punctualにエリアライトの定義が無く、FBXのエリアライトはassimpが 未対応種別として扱うため、いずれの形式からも読み込めない。
  • Position/Directionは.kmodel内ではモデル自身の ローカル空間のまま保持される。複数モデルをシーン上へ配置する場合(下記4.7)、 Assets::LoadSceneが各ModelInstance::Worldでワールド空間へ変換し、 .kscene自身の[Light]セクションのライトと合成した Scene::Lightsとして返す。

4.6.2 パッケージ読み込みと並列プリフェッチ

.kmodelが参照するユニークな.ktexは、ModelLoader.cpp内の TextureLoader::LoadAllがワーカースレッドで並列にデコードする。パック済みの .ktexは既にBC7圧縮・ミップ生成済みのDDSペイロードを持つため、ランタイム側では RHI::TextureImage::LoadFromPackedTextureによるファイル読み込み+DDSデコードのみが 発生し、WICデコード・ミップ生成・GPU BC7圧縮は一切走らない(これらは全てKurenaiPacker.exeが パック時に済ませている)。デコード自体はGPUデバイスを必要としないためワーカースレッドで 並列化できるが、GPUリソース化(device.CreateTextureFromImage)はデバイスに紐づく 処理のため呼び出し元スレッドで直列に行う。テクスチャ個別の読み込みに失敗した場合は、 スロットの種類に応じて白/フラット法線/マゼンタのプレースホルダーへフォールバックし、 モデル全体の読み込みは継続する。

各メッシュのノード変換(ワールド行列)はパック時に頂点座標へ焼き込み済みのため、 Model自体を描画する分には別途ワールド行列を掛ける必要はない (複数モデルをシーン上の別位置へ配置する場合は下記4.7のAssets::LoadSceneを使う)。 頂点レイアウトはPOSITION(R32G32B32_Float, offset=0), NORMAL(R32G32B32_Float, offset=12), TEXCOORD0(R32G32_Float, offset=24), TANGENT(R32G32B32A32_Float, offset=32)(Assets::Vertex, 48バイト)。 インデックスは常に32bit固定。

.kmodelのバージョンがランタイムと一致しない、ファイルが壊れている、参照する .kgeom/.ktexが見つからない等、読み込みに失敗した場合は std::runtime_errorを投げる(呼び出し前と異なりフォールバック先が無いため)。 個々のテクスチャの読み込みに失敗した場合はモデル全体は読み込みを継続し、白1x1 (BaseColor/MetallicRoughness)またはフラット法線(Normal)、あるいは目立つマゼンタ色の プレースホルダーに差し替えられる。

4.6.1 パッケージ読み込みと並列プリフェッチ

.ktexはKurenaiPacker.exeがWICデコード・ミップ生成・GPU BC7圧縮を事前に済ませた DDSペイロードをそのまま格納したファイルのため、LoadModelはファイルを読んで DirectX::LoadFromDDSMemoryでデコードするだけでよく、WICデコード・ミップ生成・ BC7圧縮のいずれも実行時には発生しない。

それでも大量のテクスチャを持つモデル(Bistro等)では、ファイルI/Oとデコードの合計時間を 短縮するためLoadModelはモデル1つぶんのテクスチャ読み込みをまとめて並列化する (ModelLoader.cpp内のTextureLoader::LoadAll、論理コア数を上限8で クランプしたワーカースレッドを使う)。各ワーカーが行うのは RHI::TextureImage::LoadFromPackedTextureによるファイル読み込み+DDSデコードのみで GPUデバイスを必要としないため安全に並列化できる一方、GPUリソース作成 (device.CreateTextureFromImage)自体はデバイスに紐づく処理のため呼び出し元スレッドで 直列に行う。

5. 入力について

KurenaiEngineBase はGetAsyncKeyState/GetCursorPosのような グローバル(システム全体)の入力状態ではなく、ウィンドウスコープのメッセージベース入力API を提供します。内部でWM_MOUSEMOVE/WM_LBUTTONDOWN/WM_KEYDOWN等の ウィンドウメッセージから状態を更新するため、ウィンドウがフォーカスを失っている間は反応せず、 PostMessageによるテスト自動化(実デスクトップのカーソル・フォーカスに影響を与えない)とも 整合します。 

bool IsMouseOverWindow() const;                    // カーソルがクライアント領域内にあるか
bool IsMouseButtonDown(MouseButton button) const;   // 現在押されている状態か(継続的な操作に使う)
bool WasMouseButtonPressed(MouseButton button) const; // 直前のPumpEvents()中に押された(エッジ検出)か
bool IsKeyDown(KeyCode key) const;                     // 同上(キー)。WASD移動など「押している間」続く操作に使う
bool WasKeyPressed(KeyCode key) const;                 // 同上(キー)。オートリピートは無視する
POINT GetClientMousePosition() const;               // クライアント座標(原点は左上、Y-down)
  • MouseButton は Left/Right/Middle の3値。
  • KeyCode はWin32仮想キーコード(VK_ESCAPE、'A'〜'Z'など) をそのまま使う int のエイリアス。GetAsyncKeyStateで使っていたキー定数を そのまま流用できる。
  • Is*Down系は「現在押されている状態」を返すレベル状態。WASD移動のような 「押している間」継続する操作に使う。Was*Pressed系は「離れた状態から押された状態になった」 エッジのみを検出する。判定対象の期間は直前のPumpEvents()呼び出し中 (1フレームにつき1回呼ぶ想定)。
  • GetClientMousePositionが返す座標はWin32標準のクライアント座標(原点は左上、Y-down)。 KurenaiEngine2D::DrawSpriteのワールド座標(原点は左下、Y-up。3.1節参照)とは上下が逆なので、 スプライト座標と突き合わせる場合はheight - yで変換すること。
  • これらはいずれもKurenaiEngineBaseのメンバなのでKurenaiEngine2D/ KurenaiEngine3Dどちらからも呼べる。KurenaiEngine3D::Run()自身も 移動(WASD/E/Q)・速度切り替え(Shift)・ImGui表示切り替え(F1)にこのAPI(IsKeyDown/ WasKeyPressed)を使っており、PostMessageによるキー操作のテスト自動化と 整合する。ただし右クリックドラッグによる視点回転(マウスルック)だけは意図的に例外で、 実カーソルの位置取得・固定(GetCursorPos/SetCursorPos)による無限ドラッグを 実現するためGetAsyncKeyState(VK_RBUTTON)のままにしている。これにより PostMessageでWM_RBUTTONDOWNを送っても実カーソルの位置・表示状態には 一切影響しない(意図しないカーソル操作の経路にならないことを構造的に保証している)。
  • 複数キー・複数ボタンの同時押しにも対応(それぞれ独立して状態を保持)。マウスホイールは未対応。
  • IsMouseOverWindowは、環境変数KURENAI_INPUT_AUTOMATION=1が設定されている 場合に限り、下記のImGui側と同様の理由でTrackMouseEvent由来のWM_MOUSELEAVE ノイズを抑制する。実カーソルがウィンドウ外にある状態でPostMessageにより WM_MOUSEMOVEを注入すると、直後に実カーソル位置に基づくWM_MOUSELEAVEが 割り込み、素朴に実装するとIsMouseOverWindowが真になった直後に偽へ戻ることを 繰り返してしまう。これを防ぐため、直近100ms以内にWM_MOUSEMOVEを処理していれば、 その後届いたWM_MOUSELEAVEは古い実カーソル位置によるノイズとみなして無視する (実際にウィンドウ外に出た場合も、新たなWM_MOUSEMOVEが来ない限りこの猶予はすぐ 過ぎるため、通常どおり検出される)。この環境変数は自動操作テストのハーネスが対象exeの起動前に 設定する想定のもので、未設定の通常起動ではこの抑制ロジック自体が完全に無効となり、 実際のマウス操作には一切影響しない。
  • ImGuiパネルの操作(ボタンクリック等)をPostMessageで行う場合、 WM_MOUSEMOVE → WM_LBUTTONDOWN → WM_LBUTTONUPの3つを 間隔を空けずに連続送信すること。Dear ImGuiのWin32バックエンド (imgui_impl_win32.cpp)は、ウィンドウがフォーカスされている間かつ 直近に有効なマウス位置追跡が無い場合、実カーソル位置(GetCursorPos)を毎フレーム ポーリングしてio.MousePosに上書きするフォールバック動作を持つ。さらに TrackMouseEventによるWM_MOUSELEAVE検出も実カーソル位置基準のため、 実カーソルがウィンドウ外にある状態でWM_MOUSEMOVEを送ると、ほぼ即座に(実カーソルの 位置に基づく)WM_MOUSELEAVEが発生し、次のフレームで実カーソル位置へ上書きされてしまう。 3メッセージを間隔を空けずに送ることで、この上書きが発生する前に同一フレーム(またはごく近い フレーム)内でクリック判定を完了させられる。

6. サウンド再生について

KurenaiEngineBase はXAudio2による簡易なサウンド再生APIを提供します。WAV(PCM)ファイルの 読み込み・再生・停止に対応した最小限の実装で、音量変更等は行えません(効果音・BGM程度の単純な再生が目的)。 

SoundHandle LoadSound(const std::wstring& filePath);
VoiceHandle PlaySound(SoundHandle sound, float volume = 1.0f, bool loop = false);
void StopSound(VoiceHandle voice);
  • LoadSound はWAV(PCM)ファイルを読み込み、SoundHandleを返す (TextureHandleと同様、ロード時にまとめて呼び、返ってきたハンドルを保持しておいて PlaySoundに渡す)。
  • PlaySound は呼び出しのたびに新しいボイスを生成するため、同じサウンドを重ねて (前の再生が終わる前に再度)鳴らすことができる。volumeは0.0〜1.0。戻り値の VoiceHandleはStopSoundに渡す再生中ボイスの識別子。
  • loop=trueの場合、そのボイスはStopSoundで明示的に止めるか KurenaiEngine2D/KurenaiEngine3Dが破棄されるまで無限ループし続ける。 単発再生(loop=false)は自動的に終了するため、通常StopSoundを呼ぶ必要はない (呼んでも問題はない)。
  • これらはKurenaiEngineBaseのメンバなのでKurenaiEngine2D/ KurenaiEngine3Dどちらからも呼べる。
  • 使用にはCOM初期化(CoInitializeEx)が必要(WICテクスチャ読み込みと同じ要件。 8章参照)。

7. ビルドに必要な追加の依存ファイル

KurenaiEngine3D/KurenaiEngine2D/Library のいずれを 使う場合でも、サンプルプロジェクト自身がDirectXTexのヘッダー・ライブラリを直接参照する 必要はありません(KurenaiEngineLibrary.dll内部にリンク済み)。assimpは KurenaiEngineのいずれのDLLにもリンクされていない(モデル解析はすべてオフラインの KurenaiPacker.exe側で行うため)。サンプルプロジェクトに必要なのは以下だけです。

  • インクルードディレクトリ: KurenaiEngine\Source\Engine (Libraryも使う場合は KurenaiEngine\Source\Library も追加)
  • KurenaiEngineLibrary.vcxproj と、使う方(KurenaiEngine3D.vcxproj または KurenaiEngine2D.vcxproj)への2つのプロジェクト参照(自動的に両方の インポートライブラリがリンクされる。DLLを経由した参照は推移的にリンクされないため、 Libraryへの参照だけを省略することはできない)
  • 実行時に上記2つのDLLが実行ファイルと同じフォルダに存在すること

一方KurenaiPacker.exe(Tools\KurenaiPacker\KurenaiPacker.vcxproj)は assimp・DirectXTexに加えKurenaiEngineLibrary.vcxprojへの依存を持つ (RHI::TextureImageによるBC7圧縮を利用するため)。アセットを.gltf/ .fbxから.kmodelへ変換する場合のみビルド・実行が必要で、詳細な ビルド手順・コマンドラインはREADME.mdを参照。

DrawRoundedRectの角丸半径cornerRadiusPixelsがwidth/heightの半分より大きい値の場合、ピクセルシェーダー側で半幅・半高さの小さい方に自動的にクランプされる(矩形からはみ出す角丸にはならない)

アセットの事前変換が必須Assets::LoadModelは.kmodelのみを受け付ける。.gltf/.fbx等のソースモデルは、実行前にKurenaiPacker.exeで変換しておく必要がある(7章参照)
ポイント/スポットライトの影影を落とさない(シャドウマップは平行光1灯のみ対応)
